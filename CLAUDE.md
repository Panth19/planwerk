# Planwerk

Sozialplan calculator for employment lawyers: the negotiated parameters of a German
Sozialplan in, every employee's severance out, as a web app, an Excel model, an MCP
server and an AI assistant. Users are lawyers who trust their spreadsheet more than
any app. Every design decision follows from that.

## Commands

```bash
python3 -m pytest -q                          # everything (~12 s, needs node + soffice)
python3 -m pytest -q -m "not libreoffice"     # without the Excel parity test (~1 s)
python3 -m planwerk.cli calc                  # sample case summary
python3 -m planwerk.cli serve                 # http://127.0.0.1:8765
python3 -m planwerk.mcp_server                # MCP over stdio (also in .mcp.json)
python3 scripts/screenshot.py                 # needs a running server
```

## Non-negotiable

1. **Three engines, one result.** Python, JavaScript and the Excel formulas must agree to
   the cent for every row. Any arithmetic change goes into all three in the same commit,
   and `tests/test_js_parity.py` and `tests/test_excel_parity.py` stay green. Never loosen
   a parity assertion; find the operation that differs.
2. **Same operations, same order.** Floats are compared with `==` across engines. No
   `sum()` on floats in Python (compensated summation since 3.12), use a loop. All rounding
   goes through `clean()` / `round_step()` and `ROUND(x,6)` in Excel.
3. **No client data in the repo, the logs or a cloud prompt.** Only
   `data/sample_case.json` (synthetic, generated by `scripts/make_sample.py`) is allowed.
   Anything sent to a model goes through `privacy.llm_view` and `privacy.assert_clean`.
   Logs carry fingerprints and totals, never names, dates or salaries.
4. **The model never does arithmetic on money.** The assistant calls the engine and
   quotes it. If you add an assistant feature, add a tool, not a prompt that "calculates".
5. **The UI text is the contract.** The Sozialplan wording in `web/index.html` (DE and EN)
   must describe exactly what the engine does. Change both or neither.

## Conventions

- Python 3.11+, type hints, dataclasses, no new dependencies without a reason in the PR.
- Domain terms stay German where lawyers use them (Sockelbetrag, Höchstbetrag, Stichtag,
  Anlage 1); code identifiers are English. Glossary in docs/RULES.md.
- UI strings: both languages, sentence case, German written like a lawyer writes.
- Every bug fix gets a regression test named after the behaviour, not the bug number.
- Commits: `feat|fix|docs|test|chore(scope): what changed for the user`.

## Hooks and agents (see .claude/)

- `guard_data.py` blocks writing case data, IBANs, tax or SV numbers into the repo.
- `guard_bash.py` blocks force pushes, uploads, deletes outside the repo, red commits.
- `after_edit.py` runs the tests that guard the file you just edited. If it fails,
  fix it before doing anything else.
- `before_stop.py` keeps the session going until the suite is green.
- Subagents: `parity-checker`, `legal-rules-reviewer`, `privacy-auditor`, `ui-builder`,
  `release-manager`. Use the reviewers before you call a change to rules or data flow done.

## When working in parallel

Lanes are in the map above. Each lane works in its own worktree and touches only its files.
The parity tests are the interface between lanes: the engine lane may change behaviour only
together with the test that pins it; other lanes treat the engine as read-only. Details and
the incident log in ORCHESTRATION.md.
